## 비주얼 컨셉: 「모래 위의 종이 극장」

투기장은 본래 관중을 위한 **무대**다. 이 게임은 그 무대를 **종이 인형극**처럼 보여준다.

- 인물은 관절마다 잘린 **종이 컷아웃 인형**이다. 페인터리 질감은 살리고, 움직임은 관절 회전 위주로 뚝뚝 끊어지게 만든다.
- 배경은 여러 장의 **오려낸 종이 판**을 깊이별로 세운 디오라마다. 판마다 그림자가 떨어지고, 카메라가 움직이면 판들이 서로 다른 속도로 미끄러진다.
- 조명은 **횃불과 석양의 측광**이다. 판과 판 사이로 빛줄기와 먼지가 지나간다.

이 조합은 한정된 리소스로도 깊이감이 크고, 파츠 재조합으로 수백 명의 검투사를 만들 수 있어 절차 생성과 잘 맞는다.

## 초상화 시스템 (UI 전반)

관리 화면에서 가장 많이 보는 그림이다. **흉상 페인터리 초상화**를 파츠 레이어로 합성한다.

```
레이어 순서 (아래 → 위)
1. 배경판       : 출신국 문양 + 신분별 테두리 (노예=녹슨 쇠, 자유민=청동, 해방민=금)
2. 몸통·의복    : 스타일·방어구에 따라
3. 얼굴 베이스  : 종족 × 체형 (종족당 4~6종)
4. 피부 디테일  : 주름(나이), 문신, 출신 문양
5. 흉터         : 영구 손상·흉터 특성과 연동 (경기에서 얻으면 즉시 반영)
6. 눈           : 외눈 특성이면 안대
7. 머리·수염    : 종족별
8. 투구         : 장착 시 (초상화 설정에서 숨김 가능)
9. 상태 오버레이 : 부상 붕대, 피로(어두운 눈가), 사기(표정 3단계)
```

- **흉터·안대·붕대가 초상화에 바로 쌓이는 것**이 핵심이다. 오래 굴린 검투사일수록 얼굴에 역사가 남는다.
- 나이가 들면 주름 레이어와 머리색(회색)이 단계별로 바뀐다.
- 사망한 검투사의 초상화는 채도가 빠지고, 종이 찢김 테두리가 붙어 **명예의 전당**에 걸린다.

### 파츠 수량 목표 (MVP)

| 파츠 | 수량 |
|---|---|
| 얼굴 베이스 | 7종족 × 4 = 28 |
| 머리·수염 | 종족당 6~8 |
| 흉터 | 15 (종족 공용, 색 보정) |
| 투구 | 10 |
| 몸통·방어구 | 12 |
| 표정 | 3단계 × 얼굴 베이스 |
| 배경판 | 6국가 × 3신분 |

## 하이라이트 컷 (종이 극장 연출)

### 구성

```
[원경 판]   하늘·도시 실루엣              ← 거의 안 움직임
[중경 판]   관중석 원경 (색 덩어리)       ← 천천히
[근경 판]   관중석 근경 (실루엣 관중, 팔 흔들기 리깅)
[무대 판]   경기장 벽·깃발·횃불
[바닥 판]   모래 바닥 + 그림자
[인물]      종이 컷아웃 리깅 캐릭터 2명 (또는 단체)
[전경 판]   기둥·쇠사슬·흩날리는 먼지     ← 가장 빠르게
[효과]      빛줄기, 모래 파티클, 피 튀김(종이 조각 형태), 비네팅
```

- 판마다 **살짝 거친 오려낸 가장자리 + 아래로 떨어지는 그림자**를 줘서 종이 질감을 만든다.
- 카메라는 짧게 **밀고 들어가기(push-in) + 미세한 흔들림**만 쓴다. 판 이동량 차이로 입체감이 생긴다.
- 컷 길이는 2~4초. 경기 흐름을 끊지 않게 클릭하면 바로 넘길 수 있다.

### 컷 목록과 연출 메모

| 컷 | 연출 |
|---|---|
| 입장 | 양쪽 문에서 종이 인형이 걸어 나옴. 관중 판이 들썩임 |
| 일격 / 처형 | 0.2초 정지 프레임 → 무기 궤적이 종이 조각처럼 흩어짐 |
| 종족 스킬 | 종족별 전용 포즈 (미노타우로스 뿔 돌진, 엘프 바람 걸음 등) |
| 역전 | 쓰러졌던 인형이 관절부터 다시 일어섬, 횃불이 확 밝아짐 |
| 미시오 판정 | 관중석 근경 → 주최석 클로즈업 → 엄지 (위: 횃불색 / 아래: 선혈색) |
| 사망 | 소리가 끊기고, 인형이 관절이 풀리며 쓰러짐. 색이 서서히 빠짐 |
| 해방 | 관중이 목검을 흔듦. 검투사가 목검을 받아 듦 |

### 유혈 표현

피는 숨기지 않는다. 다만 **페인터리 질감**으로 그려서 싸구려 스플래터가 아니라 무게 있는 장면으로 보이게 한다.

| 상황 | 표현 |
|---|---|
| 명중 | 상처 부위에서 피가 튐 (붓 자국 형태의 피 파티클 + 종이 조각) |
| 치명타 | 큰 피 줄기 + 0.2초 정지, 화면 가장자리 붉은 플래시 |
| 누적 피해 | 리깅 캐릭터의 몸통·팔 파츠 위에 **상처·피 얼룩 오버레이**가 HP 비율에 따라 단계적으로 쌓임 (3단계) |
| 바닥 | 피격 위치의 모래에 **피 웅덩이 데칼**이 남고 경기 끝까지 유지 |
| KO | 쓰러진 자리 주변으로 피가 번짐 |
| 사망 | 마지막 일격에 큰 피 분출 → 소리가 끊기고 인형의 관절이 풀리며 쓰러짐 → 피 웅덩이가 퍼지는 동안 화면 채도가 빠짐 |
| 초상화 | 경기 직후 초상화에 피 묻은 얼굴·붕대 레이어 표시 (다음 주에 붕대만 남음) |
| 텍스트 중계 | 부위와 상처를 구체적으로 서술 ("삼지창이 허벅지를 꿰뚫는다. 모래가 붉게 젖는다.") |

설정에 **유혈 표현 단계**(강함 / 보통 / 약함)를 둔다. 기본값은 `강함`이다.

## UI 톤

| 요소 | 방향 |
|---|---|
| 바탕 | 숯 어둠 + 아주 옅은 종이 결 텍스처 |
| 패널 | 찢긴 가장자리의 양피지 판, 또는 청동 테두리 석판 |
| 제목 서체 | 명조 계열 (예: Noto Serif KR) |
| 본문·수치 | 가독성 높은 고딕 (예: Pretendard). 수치 표는 고정폭 숫자 |
| 강조 | 횃불색 = 선택·긍정, 선혈 = 위험·사망·미납 |
| 아이콘 | 단색 청동 실루엣 (무기군, 스타일, 특성) |

- FM식 정보 밀도가 높은 화면이 많으므로, **분위기는 테두리와 배경에, 가독성은 본문에** 둔다.
- 급료 미납, 반란 위험, 부상 같은 경고는 화면 가장자리의 붉은 비네팅으로 은근히 압박한다.

## 제작 방식과 도구

| 용도 | 방식 |
|---|---|
| 이미지 | **Codex CLI 이미지 생성**. 파츠 하나당 투명 배경 PNG 하나. 프롬프트와 출력 경로는 [asset_prompts](asset_prompts.md)에서 관리 |
| 리깅 | **코드 리깅**. 본(뼈) 계층을 JSON으로 정의하고, 각 본에 파츠 스프라이트를 붙인 뒤 회전·이동 키프레임을 코드로 보간 |
| 웹 렌더링 | PixiJS (패럴랙스 레이어, 파티클, 리그) |
| Unity 이식 | 같은 본 계층 JSON과 키프레임 JSON을 읽는 C# 리그 플레이어를 만든다. 파츠 PNG는 그대로 사용 |

### 코드 리깅 구조

```
rig/skeleton.json   본 계층: root → pelvis → torso → head / upper_arm_l → forearm_l → hand_l ...
                    각 본: 부모, 길이, 피벗(파츠 이미지 안의 관절 위치)
rig/anims/*.json    애니메이션: 본별 회전·이동 키프레임 + 이징
                    (idle, walk_in, attack_slash, attack_thrust, hit, fall, die, raise_arms)
rig/skins/*.json    종족·장비별로 어떤 파츠 PNG를 어느 본에 붙일지
```

- 종이 인형 느낌을 위해 보간은 **약간 끊기게**(stepped ease) 하고, 관절 회전 위주로 움직인다.
- 상처·피 얼룩 오버레이는 본에 붙은 자식 스프라이트로 넣어서 몸과 함께 움직인다.

**웹 단계 진행 순서**

1. 플레이스홀더(단색 실루엣·이니셜 초상화)로 시스템 먼저 완성
2. Codex CLI로 초상화 파츠 생성 → 합성
3. 패럴랙스 배경 1세트 (속주 투기장)
4. 리그 파츠 생성 → 코드 리깅 → 하이라이트 컷

### 파츠 명명 규칙 (웹·Unity 공용)

```
portrait/{race}/{layer}/{id}.png       예) portrait/orc/face/02.png
rig/{race}/{skin}.json                  예) rig/minotaur/heavy_armor.json
arena/{nation}/{layer_index}_{name}.png 예) arena/kemer/03_crowd_near.png
```

데이터의 `portraitParts` 필드가 이 ID를 참조한다 ([10 기술 구조](10_tech.md)).
